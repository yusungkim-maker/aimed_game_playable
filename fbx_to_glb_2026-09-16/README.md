# FBX → glb 전환 작업 보관함 (2026-09-16)

2026-09-16 FBX 임포터 장애 대응으로 프로젝트의 `.fbx` 59개를 `.glb`로 전환했다.
전체 경위는 `../FBX임포터_장애분석_2026-09-16.md`, 현재 상태는 프로젝트 `CLAUDE.md`의
"✅ FBX 임포터 장애" / "📦 캐릭터 에셋 = glb" 두 절에 있다.

## 폴더

| 경로 | 내용 |
|---|---|
| `glbout/` | **변환본 59개 전부.** 프로젝트에는 이 중 51개만 설치했다(실사용 10 + 모션 라이브러리 41). 나머지 8개는 중복 사본이라 제외 |
| `bak_before_remap/` | **uuid 리맵 직전의 씬·프리팹·애니그래프 원본 10개.** 되돌려야 하면 이걸 제자리에 덮어쓴다 |
| `scripts/` | 재현용 스크립트 4개 + 생성된 대응표 2개 |

## scripts

| 파일 | 역할 |
|---|---|
| `convert_all.js <출력폴더>` | `.fbx` 전수를 변환기로 돌려 `.glb` 생성. **애니메이션 이름을 백업 meta의 split 이름으로 패치**하는 것이 핵심 (원본 take 이름은 `Take 001`이라 그대로 두면 코드·애니그래프가 조용히 깨진다) |
| `usage.js` | 각 `.fbx`가 프로젝트 어디에서 참조되는지 전수 조사 → `usage.json`. 실사용/미사용을 가르는 근거 |
| `build_remap.js` | 구 서브에셋 id → 신 서브에셋 id 대응표 생성 → `remap.json` |
| `apply_remap.js [--write]` | 씬·프리팹·애니그래프의 uuid 치환. 인자 없으면 드라이런 |

**주의**: 스크립트 안의 경로는 2026-09-16 시점 기준으로 하드코딩되어 있다. 재사용하려면 상단 상수를 고칠 것.

## 이 작업에서 얻은 사실

- 서브에셋 id는 **클립 이름에서 결정**되므로 재변환해도 같은 값이 나온다(실측 8/8 일치). 바뀌는 건 부모 uuid뿐이라 리맵이 단순하다.
- 변환기는 에디터 번들본을 쓴다: `C:\ProgramData\cocos\editors\Creator\3.8.8\resources\app.asar.unpacked\node_modules\@cocos\fbx-gltf-conv\bin\win32\FBX-glTF-conv.exe`
  기본 옵션으로 돌리면 메시 수·스켈레톤 수·본 이름·정점 수가 에디터 임포트 결과와 동일하다(실측 확인).
- `.glb` 총 5.3MB vs 원본 `.fbx` 19.2MB.
- **임시·백업 파일을 `assets/` 안에 만들지 말 것.** 에디터가 에셋으로 등록해버려 삭제도 Assets 패널을 거쳐야 한다(이번에 `.bak` 10개로 실제로 겪었다).
