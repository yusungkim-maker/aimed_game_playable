# Cocos Creator 3.8 — 애니메이션 & 피직스

## 1. 애니메이션

- **SkeletalAnimation + Skeleton**: glTF/glb로 임포트한 스켈레톤 기반 캐릭터 애니메이션에 사용. `SkinnedMeshRenderer`가 스켈레톤에 바인딩된 메쉬를 렌더링한다.
- **중요한 함정**: `SkinnedMeshRenderer`/`SkeletalAnimation`은 소스 glTF에 실제 스켈레톤·애니메이션 클립 서브 에셋이 있을 때만 유효하다. 스켈레톤 없는 정적 메쉬(예: 단순 Plane)에 이 컴포넌트를 잘못 붙이면 `_skeleton`/`_defaultClip` 참조가 허공(dangling uuid)을 가리키게 되어 렌더링이 아예 실패한다 (메쉬가 안 보임). 스켈레톤 없는 오브젝트는 그냥 `MeshRenderer`를 쓰고, 움직임이 필요하면 스크립트로 직접 애니메이션(예: bob 모션)을 구현한다.
- **Spine 2D**: 별도 미들웨어. 프로젝트에 Spine 관련 참조가 하나라도 있으면 전체 빌드에 Spine 런타임이 번들링되므로, 안 쓰면 완전히 제거하는 게 용량에 유리하다 (02번 문서 참고).

## 2. 피직스 엔진 — 4종 비교

Cocos Creator 3.8은 프로젝트 설정(`Project → Project Settings → Feature Cropping`)에서 피직스 엔진을 선택할 수 있다. 선택에 따라 빌드 용량이 크게 달라진다.

| 엔진 | 대략적 용량 | 특징 |
|---|---|---|
| **Builtin** | 최소 | 충돌 감지(collision)만 지원, 물리 시뮬레이션 없음 |
| **Cannon.js** | ~141KB | 리지드바디, 레이캐스팅, 피직스 머티리얼 등 준수한 기능 |
| **Bullet (ammo.js)** | ~1.5MB | 미니게임 플랫폼 전반에서 좋은 물리 품질+성능, 미니게임에 권장 |
| **PhysX** | ~5MB | 가장 완전한 기능·안정성, 네이티브(특히 iOS)에 적합. 미니게임/안드로이드 x86에는 부적합 |

**플레이어블 광고처럼 용량이 극도로 민감한 경우**: 실제로 충돌 판정 정도만 필요하면 Builtin으로, 리지드바디 시뮬레이션이 꼭 필요하면 Cannon.js가 가장 합리적인 절충점. Bullet/PhysX는 특별한 이유(복잡한 물리 반응이 코어 재미 요소인 경우)가 없으면 플레이어블 광고에는 과함.

**주의**: 빌드에 실제로 어떤 피직스 라이브러리가 포함됐는지는 빌드 파일 내부 코드에 특정 로더 문자열이 보인다고 곧바로 판단하면 안 된다 — 실제 wasm/바이너리 데이터가 진짜로 존재하는지 직접 디코딩해서 확인해야 한다 (제네릭 로더 코드 문자열만 있고 실제 데이터는 없는 false-positive 사례가 있었음).
