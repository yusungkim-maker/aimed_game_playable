# 타이쿤 플레이어블 기획서 v2 — 캐고, 팔고, 투자하고, 더 크게 회수한다

작성일: 2026-09-16 · 기획/에셋 준비: Codex · 기능 개발: Claude Code

**최신 기준 문서. v1의 ‘목재를 바로 건물에 지불하는 단일 재화 경제’를 대체한다.** 사용자가 확정한 대전제는 자원 획득→가공 또는 직접 판매→재화 획득→눈에 띄는 업그레이드→수급 가속→한 사이클의 보상 회수 후 종료다. 아래 소재 선택·가격·시간은 이를 구체화한 테스트 제안이며 아직 구현하거나 플레이 검증하지 않았다.

## 1. 게임 기획

### 1.1 핵심 재미와 방향

**나무를 베어 등을 채우고, 판매 소켓에서 나무를 연속으로 쏟아 코인을 받고, 업그레이드 소켓에 코인을 연속 투입한다. 투자한 결과로 더 쉽게·더 많이 모아 다시 큰 판매 대금을 회수한다.**

소켓은 ‘정해진 자원이나 재화를 받아 조건에 맞는 결과를 내는 영역’이다. 판매대, 가공기, 건설·고용 구역 모두 이 개념으로 설명할 수 있다. 플레이어가 반복할 핵심 행동은 **모으기 → 쏟기 → 받기 → 다시 쏟기**다. 이동과 경제는 이 행동을 반복하고 증폭시키기 위한 구조다.

‘도파민’은 사용자가 설명한 보상감의 기획 표현으로 사용한다. 신경학적 효과를 측정했다는 뜻이 아니다. 실제 판단은 조작 지속, 재투입 의향, 성장 인지, 설치 전환으로 한다.

| 항목 | v2 기본안 |
|---|---|
| 방향 | 채집·판매·재투자로 성장하는 아케이드 타이쿤 플레이어블 |
| 자원 | 목재 1종 |
| 소비 재화 | 코인 1종. 목재와 코인은 별개의 보관·회계·비주얼 |
| 채택 루프 | 목재 직접 판매. 가공은 후속 변형안이며 기본안 필수 단계가 아님 |
| 조작 | 한 손 드래그 이동, 범위 내 자동 벌목·획득, 소켓 체류 시 자동 투입 |
| 핵심 투자 | 한 방 벌목 / 자동 벌목·판매 일꾼 / 구역 확장과 두 번째 일꾼 |
| 필수 투자 횟수 | 3회 |
| 목표 길이 | 첫 입력 이후 45~60초. 진도는 이벤트 기반 |
| 전투 | 몬스터 0, 사냥·HP·기지 방어 없음. 이번 소재는 벌목 |
| 종료 | 마지막 투자 뒤 커진 채집·판매 사이클을 실제로 끝낸 순간 |

**직접 판매를 기본으로 택한 이유:** 현재 목재·캐릭터·건물 준비물로 채집, 판매, 현금 회수, 투자, 자동화를 모두 구현할 수 있다. 초기 버전부터 판자·가공 대기·별도 운반을 추가하면 핵심 소켓 체험의 빈도와 첫 투자 도달 속도를 낮출 수 있다. 사용자의 ‘가공하거나 그대로 판매’ 원칙 안에서 직접 판매 경로를 먼저 검증한다.

### 1.2 세 가지 후킹

1. **쌓고 비우는 만족감:** 6개씩 얻은 나무가 등에 쌓이고, 판매대에서는 하나씩 빠져나간다. 화면에서 자원의 이동이 보인다.
2. **판매 대금의 재투입:** 나무가 빠진 자리에서 코인이 연속으로 나오고, 그 코인이 새 설비·일꾼을 만드는 다음 소켓으로 들어간다.
3. **똑같은 행동이 커지는 성장:** 첫 나무는 세 번, 업그레이드 뒤에는 한 번에 벤다. 뒤이어 일꾼도 나무를 판매한다. 마지막에는 내 등짐과 일꾼의 판매가 합쳐져 처음보다 큰 대금을 회수한다.

코인 숫자만 올라가는 판매, 가격만 바뀌는 건설, 일꾼이 등장만 하고 끝나는 광고는 이 기획의 완료 상태가 아니다.

## 2. 소켓 체험의 구체적 설계

### 2.1 소켓의 기능을 구분한다

| 소켓 종류 | 입력 | 결과 | 진행·한도 |
|---|---|---|---|
| 판매 소켓 | 목재 | 목재 1개당 코인 5 | 반복 가능, 판매 수량 표시. 특정 수량을 채워야만 판매되는 구조 아님 |
| 업그레이드 소켓 | 코인 | 설비 개선·일꾼·구역 확장 | 지정 가격까지 분할 납부, 완료 보상은 1회 |
| 가공 소켓 / 확장안 | 목재 | 판자 등 다른 아이템 | 제작 큐·출력 보관·대금 회수는 별개 단계. 기본 빌드에서는 비활성 |

판매는 자원을 받아 재화를 반환하는 소켓이다. 업그레이드는 재화를 받아 성장 보상을 반환한다. 기존 소켓 스크립트가 모든 타입을 지원한다고 가정하지 않으며, Claude가 공통 입력·진행·보상 로직을 재사용할 지점을 확인한다.

### 2.2 쏟아지는 연출의 규칙

| 행동 | 보이는 변화 | 제안 시간 / 피드백 |
|---|---|---|
| 벌목 | 타격마다 나무 반응, 마지막 타격에 나무 제거·통나무 발생 | 최초 준비 0.20초, 타격 간격 0.40초, 끝난 후 회복 0.20초 |
| 자원 획득 | 땅→등짐으로 순차 이동, 쌓이는 높이 변화 | 통나무 비행 0.25초, 출발 간격 0.04초 후보 |
| 판매 투입 | 등짐→판매대, 등짐 수량과 판매 누계 변화 | 목재 1개당 0.10초. 소켓 인식 피드백 즉시 |
| 대금 회수 | 판매대 지급함에 코인 생성→플레이어 지갑 방향으로 흡수 | 판매 인정 후 0.15초 뒤부터 회수, 토큰 비행 0.25초 |
| 투자 투입 | 지갑/플레이어 위치→업그레이드 소켓으로 코인 흐름 | 0.08초마다 최대 5코인. 마지막에는 남은 가격만 |
| 투자 완성 | 소켓 채워짐→설비 등장→새 기능의 첫 행동 | 완성 연출 0.60초. 새 기능을 바로 써볼 수 있는 위치 |

통나무가 판매대에 도착할 때 판매를 확정한다. 장부상 매출은 그때 발생하며, 지갑에는 지급함의 코인을 실제 회수할 때 들어간다. 투자할 수 있는 돈은 지갑 잔고뿐이다. 연출과 장부 사이의 상태를 건너뛰어 같은 자원을 두 번 지급하지 않는다.

코인 시각 토큰 하나는 **5코인짜리 묶음**으로 정한다. 기본 판매 6개는 6개의 묶음이 순차 생성되어 총 30코인이다. 최종 큰 판매에도 숫자만 한 번 띄우지 말고 제한된 토큰을 계속 재사용해 흘려보낸다. UI에는 코인 아이콘과 실제 금액을 함께 표시한다.

목재 소켓은 목재 아이콘, 투자 소켓은 코인 아이콘으로 구분한다. 색만으로 구분하지 않는다. 가격은 `납입액/필요액`, 판매는 `이번 판매 +30`처럼 표현한다. ‘0/6’ 같은 판매 목표 표시는 목표 수량이고 최소 거래량이 아님을 구분한다.

### 2.3 코인 회수에서 불필요한 왕복을 만들지 않는다

판매 구역과 지급함 회수 범위가 겹치도록 둔다. 플레이어가 판매 소켓에서 머무르면 목재 투입과 대금 회수가 이어진다. 판매 후 별도의 먼 코인 더미로 이동할 필요가 없다.

일꾼은 같은 판매대의 별도 납품 위치를 이용한다. 일꾼 매출은 지급함에 쌓이며 **플레이어가 판매대에 방문하여 회수**한다. 자동 채집·운반·판매가 생겨도 ‘돈을 모아 투자하는 마지막 손맛’은 플레이어에게 남는다. 지급함 코인 모델은 최대 8개이고 실제 잔액은 숫자로 정확하게 표시한다.

## 3. 시작부터 종료까지의 흐름

### 3.1 시작 상태

플레이어의 목재·코인은 모두 0. **판매대는 처음부터 영업 중**이다. 나무, 상인, 목재→코인 아이콘이 붙은 판매 구역이 첫 화면에 함께 있다. 판매로 돈을 벌기 전에 판매대부터 건설해야 하는 자금 막힘을 만들지 않는다.

첫 안내는 ‘나무를 모아 팔아 보세요’. 첫 터치는 이동이고, 처음에는 첫 나무만 안내한다. 목재가 생기면 판매대로, 코인이 생기면 첫 투자 소켓으로 안내 대상을 바꾼다. 동시에 여러 화살표를 띄우지 않는다.

### 3.2 정상 경로

| 첫 입력 후 목표 시간 | 플레이어 행동 | 지불/수급 | 눈에 보이는 변화와 목적 |
|---|---|---|---|
| 0~3초 | 나무 1그루를 세 번 쳐서 목재 6개 적재 | 목재 +6 | 등에 쌓이는 첫 보상 |
| 3~6초 | 판매 소켓에서 6개 투입, 코인 회수 | 코인 +30 | 나무가 돈으로 바뀌는 경험 |
| 6~9초 | U1 작업대 소켓에 코인 투입 | 코인 -30 | 작업대 완성. 벌목 3타→1타 |
| 9~18초 | 업그레이드된 도끼로 2그루 채집, 12개 판매 | 코인 +60 | 첫 투자로 같은 시간에 더 크게 채우는 경험 |
| 18~23초 | U2 오두막 소켓에 투자 | 코인 -60 | 첫 자동 벌목·운반·판매 일꾼 합류 |
| 23~33초 | 본인 목재 12개 판매 + 일꾼 첫 목재 6개 판매분 회수 | 코인 +90 | 본인과 일꾼의 수익이 합쳐짐 |
| 33~36초 | U3 확장 소켓에 투자 | 코인 -90 | 새 작업 구역·길·간이 쉼터 공개, 두 번째 일꾼 합류, 등짐 12→18 |
| 36~46초 | 직접 목재 12개 판매, 두 일꾼의 각 6개 판매분 회수 | 기준 코인 +120 | 커진 경제를 한 차례 실제로 회수 |
| 약 46~50초 | 큰 판매 정산과 기지 전체를 확인 | 이번 성장 사이클 완료 | 다음 구역 예고 + 설치 CTA |

이 표는 기준 수급 경로다. 기계적으로 정해진 초가 되면 자원을 주거나 건물을 완성시키지 않는다. 직접 더 캐면 일찍 투자할 수 있고, 자동화 이후 일꾼 수익을 기다려도 진행된다.

### 3.3 업그레이드는 장식과 기능이 함께 바뀐다

| 투자 | 가격 | 외형 변화 | 실질 변화 | 다음 사이클에서 보여줄 증거 |
|---|---:|---|---|---|
| U1 벌목 작업대 | 30코인 | 빈 받침에 작업대·도끼 표식 등장 | 채집력 1→3, 같은 나무 3타→1타 | 바로 다음 나무가 한 번에 쓰러짐 |
| U2 벌목 오두막 | 60코인 | 오두막 완성, 입구에서 일꾼 등장 | 일꾼 1명이 채집→운반→판매, 8초당 목재 6개 목표 | 목재를 든 일꾼이 판매대에 납품하고 지급함 잔액 증가 |
| U3 생산 구역 확장 | 90코인 | 경계 내려감, 길·두 번째 작업 구역·쉼터 공개 | 일꾼 1→2명, 플레이어 등짐 12→18 | 두 노선의 판매, 더 높게 쌓을 수 있는 플레이어 등짐 |

U1의 순수 벌목 동작 시간은 아래 수치대로면 1.2초→0.4초다. **전체 수입 3배라고 표시하지 않는다.** 이동·수집·판매 시간이 남기 때문이다. U3의 자동 생산은 1명일 때 대비 2배지만 전체 플레이어 수익률이 정확히 2배인 것도 아니다. UI는 ‘한 방 벌목’, ‘일꾼 +1’, ‘운반 +6’처럼 실제 변경을 표시한다.

### 3.4 동선과 화면 배치

```text
              [다음 큰 기지 미리보기]
       [U3 확장 경계 → 새 작업 구역 + 일꾼2]
                        |
 [플레이어 숲] — [판매대·지급함] — [U2 오두막·일꾼1 작업 구역]
        |               |
    [시작 위치]      [U1 작업대]
```

판매대를 중심에 두고 투자 소켓을 주변에 둔다. 판매대↔현재 투자 구역은 편도 1~1.5초, 숲↔판매대는 편도 1~2초 목표다. 판매·지급함·업그레이드 소켓의 입력 영역은 겹치지 않게 하고, 회수 범위만 판매 구역과 겹친다. 의도치 않게 판매하던 중 코인이 자동 투자되는 것을 방지한다.

고정 각도의 오소그래픽 카메라를 유지한다. 코인 회수와 일꾼 판매를 볼 수 있는 방향으로 위치·줌만 조절한다. 카드 건물의 투영 각도를 바꾸지 않는다. 세로와 가로 화면 모두 플레이어·현재 목표·판매대가 이해되는 배치를 검수한다.

### 3.5 종료 조건: 마지막 투자의 결과를 회수한다

정상 종료는 다음 조건을 모두 만족했을 때다.

1. U3가 실제 완성됐다.
2. U3 이후 **획득한** 플레이어 목재 12개 이상이 판매되고, 그 판매 대금이 회수됐다.
3. U3 이후 두 일꾼이 각각 판매를 한 번 이상 완료했고, 해당 대금도 회수됐다.
4. 위 결과를 포함해 U3 이후 판매분의 회수액이 120코인 이상이다.
5. 큰 판매 정산을 최소 2초 보여준다. 그 직후 성공 패널을 띄운다.

미리 모아둔 코인이나 U3 이전 판매분을 성공 기준에 섞지 않는다. 성공 판단은 현재 지갑 잔액이 아니라 **U3 이후 자격을 갖춘 판매·회수 기록**을 쓴다. 한 번의 방문에서 모두 회수할 필요는 없고 누적으로 인정한다.

이후에도 배경은 움직일 수 있지만 새 필수 투자는 없다. ‘첫 목재 기지 완성’과 다음 구역의 실루엣, ‘더 큰 기지 만들기 · 설치’를 보여준다. 다음 구역을 실제로 열린 것처럼 속이지 않는다. 설치는 명시적인 CTA 터치에서만 실행한다.

첫 입력 이후 활성 시간 75초가 되어도 정상 조건을 못 채우면 현재 기지에 보조 CTA를 노출하고 플레이를 유지한다. 성공으로 위장하거나 강제로 끊지 않는다. 숨김 시간은 제외한다. 지면 자체의 종료 정책은 별도로 따르며 게임 시간이 광고 SDK 타이머를 대신하지 않는다.

### 4.2 기준 수급표

| 구간 | 플레이어 판매 목재 | 일꾼 판매 목재 | 판매 매출 | 투자 | 구간 종료 누적 지갑 잔액 |

필수 투자 총액은 180코인, 이를 벌기 위한 판매 목재는 36개다. 마지막 성장 확인까지 포함한 기준 판매량은 **60개**다. 플레이어 42개는 7그루 상당이고, 일꾼 18개는 6개씩 3차례 판매다. v1의 ‘60목재를 건물에 지불’과 전혀 다른 회계다.

참고 장부의 U2 완성은 22초, 일꾼1 판매는 30·38초, U3 완성은 35초, 일꾼2 첫 판매는 43초다. 마지막 플레이어 판매는 44초에 끝나며, 대금을 회수하고 정산을 보여준 뒤 약 47초에 성공 패널을 보여줄 수 있다. 이 시간은 **수급 검산용 일정**으로, 실제 이동·애니메이션까지 검증한 결과가 아니다.

첫 판매 30코인과 마지막 구간 정산 120코인은 4배 차이다. 마지막은 플레이어와 두 일꾼의 **합산 정산액**이므로 ‘판매 단가 4배’나 ‘초당 수입 4배’로 표현하지 않는다. 분할 방문 시 구간 합계로 집계하며 마지막에 중복 지급하지 않는다.

### 4.3 장부와 예외 규칙

- 목재와 코인은 별도 ID로 관리한다. 기존 이름이 Coin인 스크립트에 wood 모델이 연결돼 있다는 이유로 같은 잔고를 사용하면 안 된다.
- 목재는 `획득 누계 = 플레이어짐 + 일꾼짐 + 땅/이동 중 실제 목재 + 판매로 소비된 목재`를 만족해야 한다.
- 코인은 `매출 누계 = 지급함/회수 중 실제 코인 + 지갑 + 투자 소비 누계`를 만족해야 한다. 완성 전 부분 납부도 투자 소비에 포함한다.
- 시각 토큰은 장부의 복사본일 수 있다. 화면 모델 개수를 실제 잔고로 쓰지 않는다. 연출이 취소돼도 재화를 잃거나 중복 발행하지 않는다.
- 소켓에서 나가면 새 투입을 중단한다. 이미 접수한 목재는 예약된 거래를 정확히 완료하고, 미회수 대금은 지급함에 남긴다. 업그레이드 부분 납부도 유지한다.
- 판매 거래를 접수할 때 지급함의 가용 한도에서 판매가만큼 예약한다. 회수 중 금액도 공간에서 제외하지 않아 미완료 거래로 한도를 초과하지 않게 한다.
- 판매대가 가득 차면 플레이어·일꾼은 목재를 보유한 채 기다린다. 회수 공간이 생기면 재개한다. 바닥에 끝없이 돈이나 나무를 생성하지 않는다.
- 플레이어 등짐에는 나무 한 그루 보상 6개를 전부 담을 자리가 있어야 새 벌목을 시작한다. 수집/드롭 풀도 함께 예약한다. 부족하면 판매대를 안내한다.
- U1은 다음 새 벌목부터 적용한다. 진행 중 공격의 타격 수와 보상을 중간에 바꾸지 않는다.
- 동시에 판매해도 판매 토큰·장부·노선 예약은 소유자를 구분한다. 한 일꾼이 다른 일꾼의 목재를 빼앗지 않는다.
- 투자 구역은 현재 단계 하나만 활성화한다. 돈이 충분하더라도 플레이어가 방문해야 납부된다. 판매 구역과 겹쳐 원치 않는 지출이 발생하면 안 된다.
- 구매 완료·일꾼 등장·구역 공개는 단계당 한 번만 발생한다.
- 숨김 시 생산·판매·회수·투입을 모두 정지한다. 복귀 시 큰 dt로 자원을 한꺼번에 발행하지 않는다.
- 일꾼 수익을 기다리는 경로도 가능하고 직접 채집으로 투자를 앞당길 수도 있다. 정상 성공에는 자동화의 실제 판매가 필요하므로, 고장 난 일꾼을 건너뛰어 성공 처리하지 않는다.

## 6. Claude Code 구현 요구

### 6.1 기존 기능과의 연결

| 요구 | 문서상 재사용 후보 | 추가 확인/확장 |

위 기능은 문서에서 이름만 확인한 후보다. 현재 코드·씬 연결을 검증했다고 보고하지 않는다. 상세 전달은 `tycoon-claude-brief-v2.md`, 숫자 원본은 `tycoon-balance-v2.json`을 따른다.

### 6.2 작업 단위

1. **목재와 코인 장부 분리:** 소유권·예약·거래 상태를 구현한다. 현재 wood 렌더링을 일반 코인으로 되돌리지 않는다.
2. **판매와 회수 먼저 완주:** 목재 6개→30코인→지갑 30의 시각·장부 흐름을 검증한다.
3. **첫 투자와 재판매:** 30코인 투입→한 방 벌목→12개 판매로 투자 전후 차이를 확인한다.
4. **자동화 연결:** 60코인 일꾼→목재 판매→지급함 누적→플레이어 회수. 자동화의 각 단계가 실제로 동작해야 한다.
5. **확장과 큰 정산:** 90코인 투자→두 번째 노선→U3 이후 자격 있는 목재 판매/코인 회수 누적→성공.
6. **연출·성능·출고:** 소켓 피드백을 조정하고 5MB/실기기 기준을 통과한다.

새 클래스명은 기존 코드를 보고 정한다. 씬 전용 코드 복제나 큰 단일 매니저를 강요하지 않는다. 공통 소켓 입력과 보상은 재사용하되, 반복 거래와 1회 건설의 회계 차이는 명시한다. 모든 수치·모델·노선·품질 상한은 인스펙터 설정으로 조정 가능해야 한다.

| 씬·스크립트·효과·머티리얼 | 110,000 B |
| 내부 변경 여유 | 180,000 B |
| **합계** | **4,500,000 B** |

실측이 아닌 예산이다. 전체 압축의 기여분은 단순 가산으로 실측 분리하기 어려우므로 포함 목록·디코딩 크기·같은 조건의 증분 빌드로 검증한다. 판매 추가분은 기존 자산 재조합·군중/가공품/영상 미포함으로 관리한다. 5MB 초과 시 먼저 장식·예고 이미지·부수 음원을 줄이고, 핵심인 자원 투입·코인 회수 연출을 통째로 삭제하지 않는다.

### 7.2 런타임 상한

| 항목 | 초기 목표 |
|---|---|
| 스켈레탈 캐릭터 / 정적 상인 | 3명 / 1명 |
| 상호작용 나무 | 8그루 |
| 목재 표시 | 땅24 + 플레이어18 + 일꾼12 + 판매 비행8 = 최대62노드 |
| 코인 표시 | 지급함8 + 회수 비행8 + 투자 비행8 = 최대24노드 |
| 효과 | 동시 파티클24개 |
| 실시간 그림자 | 0패스 목표, 기존 접지 그림자 재사용 |
| 드로우콜 / 화면 삼각형 | 일반60 목표, 피크80 경고 / 50,000 이하 목표 |
| 렌더 긴 변 | 기본1280px, 낮은 등급960px 후보 |
| 프레임 | 중급60fps·p95≤20ms 목표, 낮은 등급30fps·p95≤35ms 목표 |
| 긴 정지 | 활성 플레이 100ms 초과 정지 0회 목표, p99도 기록 |
| 준비 시간 | 파일 전달 완료부터 중급2초/낮은 등급3초 목표, 다운로드 시간 별도 |

모델 개수 상한은 매 프레임 실제로 모두 보인다는 뜻은 아니다. 62+24개의 오브젝트를 개별 드로우하면 목표를 넘을 수 있으므로, 같은 메시·머티리얼 공유 및 가능한 인스턴싱을 함께 검증한다. 상한 설정 자체가 성능 보장은 아니다.

### 7.3 구현 방법

- 첫 판매 전에 코인/목재 풀, 필요한 머티리얼·효과음을 준비한다. 돈을 받을 때마다 instantiate/destroy하거나 셰이더를 처음 컴파일하지 않는다.
- 자원 토큰과 코인 토큰은 풀을 구분한다. 비주얼 풀이 가득 차면 동시 비행 수를 제한하고 연속 재사용한다. 회계는 유실 없이 진행하며 정상 경로에서 쏟아지는 연출이 사라지지 않도록 우선순위를 둔다.
- 비행은 충돌 물리 대신 짧은 곡선 보간. 화면 흔들림·빛·큰 투명 파티클보다 스택 감소, 토큰 궤적, 가격 채움, 짧은 효과음을 우선한다.
- 코인 300개를 300개 모델로 만들지 않는다. 지급함 8모델+정확한 잔액, 회수는 5코인 토큰 재사용. 음원도 토큰마다 무제한 겹치지 않게 동시 재생 수를 제한한다.
- 일꾼 2명은 고정 노선과 예약 슬롯 사용. 활성 투자 소켓1개, 판매대1개만 검사. 물리 엔진·NavMesh·손님 대기열을 새로 추가하지 않는다.
- 건물 카드의 2개 머티리얼은 면별 드로우가 생길 수 있음을 예산에 반영한다. 개별 MaterialInstance·투명 정렬·실시간 스켈레탈 캐릭터의 배칭을 자동이라고 가정하지 않는다. [Cocos MeshRenderer 제약](https://docs.cocos.com/creator/3.8/manual/en/engine/renderable/model-component.html)
- 카드 투명 여백과 겹침을 줄이되, 반투명 접지 그림자를 무조건 컷아웃으로 바꾸지 않는다. 목재/코인 불투명 반복 모델부터 공유·인스턴싱을 검토한다.
- 숫자는 변경 시만 갱신, 가이드는 목표 전환 시만 갱신. 프레임마다 새 배열/벡터/문자열 생성 최소화.
- 용량은 씬3만 포함→실제 내장 데이터 디코딩→미사용 클립·모듈 제외→화면 픽셀 기준 이미지 축소 순서. 이전 문서의 엔진 2.68MB는 현재 빌드 확정값이 아니다.
- Feature Cropping은 공유 프로젝트 설정이므로 기존 씬 영향도 확인한다. 기본값·프로퍼티 이름·uuid/CID·사용자 수동 튜닝을 보존한다. [Cocos Project Settings](https://docs.cocos.com/creator/3.8/manual/en/editor/project/)

## 8. 검증과 완료 기준

### 8.1 기획 검증

| 확인 | 내부 관찰 목표 |
|---|---|
| 첫 행동 | 새 테스트 인원5명 중4명이 첫 입력 후3초 안에 채집 시작 |
| 교환 이해 | 별도 설명 없이 ‘나무를 팔아 코인을 얻는다’를 말할 수 있음 |
| 투자 이해 | ‘소켓에 코인을 넣어서 무엇이 좋아졌는가’를 실제 기능으로 설명 |
| 성장 체감 | 첫 사이클과 마지막 사이클의 차이를 타격 수·운반·일꾼 수로 인지 |
| 반복 의향 | 첫 판매 뒤 다음 나무/투자로 스스로 이동하는지 관찰 |
| 완료 시간 | 기준 경로45~60초, 이동·판매·회수·투자·생산 시간을 각각 기록 |

초기값이므로 유저 테스트 결과에 따라 조정한다. 코인 가격부터 일괄 낮추기보다 불필요한 이동, 소켓 판정 지연, 기다림, 거래 피드백 누락을 먼저 분리해서 본다.

### 8.2 개발 검증

- 첫 판매6→30, 투자30→U1, 다음 판매12→60의 장부와 화면이 일치한다.
- 자동화 매출이 지갑에 순간 입금되지 않고 지급함에서 실제 회수된다.
- 플레이어와 두 일꾼의 동시 판매, 지급함 포화, 중간 소켓 이탈, 비행 중 숨김/복귀에서도 재화 보존.
- 기존 재고/미회수 돈으로 U3 이후 정상 종료 조건을 우회하지 않는다.
- 판매 장식 토큰을 반복 만져도 돈이 복사되지 않고 건설 보상이 재실행되지 않는다.
- 정상·빠름·느림 경로, 반복 리셋3회, 종료 후3분 실행에서 노드/리스너 무한 증가 없음.
- 낮은 등급 Android·중급 Android·iPhone 실제 WebView/공식 프리뷰에서 각3회. 첫 판매·코인 폭포·일꾼 첫 등장·최종 정산의 프레임 시간과 메모리 확인.
- 세로/가로, MRAID 준비, 첫 터치, 음소거/복귀, WebGL 실패/컨텍스트 손실 폴백, 최종 HTML 바이트를 검증.

개발 계측 이벤트: first_input, harvest_complete, sell_accepted, cash_collected, upgrade_paid, upgrade_completed, worker_first_sale, post_upgrade_settlement, success_reached, cta_shown, cta_clicked. 거래 sourceId·resourceId·upgradeEpoch로 출처와 단계 경계를 구분한다. 배포에 임의 분석 SDK/외부 요청을 추가하지 않는다.

## 9. 가공 루프 확장안과 사례 적용

가공형 변형은 **목재→가공 소켓→판자→판매 소켓→코인→업그레이드**다. 직접 판매형에서 투입·회수 체험이 검증된 뒤 별도 빌드로 시험한다. 이때 판자 ID, 입력/출력 보관, 처리 시간, 변환 비율, 판매가, 자동 운반 병목을 함께 다시 계산한다. 직접 판매형 숫자를 그대로 붙이지 않는다. 상점 메뉴 클릭으로 가공을 대체하지 않고, 입력 소켓에 쏟고 출력물을 받는 동작으로 설계한다.

v1에서 확인한 최근 사례는 참고 근거로 유지한다. 킹샷의 편한 조작에서 수집·건설·확장으로 연결되는 공개 분석은 쉬운 진입의 참고이고, 특정 판매 소켓 수치나 우리의 경제를 검증한 자료는 아니다. [Sett의 Kingshot 분석](https://www.sett.ai/content/misleading-game-ua-creatives/)

미니어처 조작과 주도권을 분석한 킹샷 영상 사례는 손으로 세계를 바꾸는 느낌을 참고한다. 실제 HTML 플레이어블 조작이나 매출 전환율을 직접 확인한 것으로 서술하지 않는다. [SocialPeta·Reforged Labs 2025 보고서, p.18](https://sp2cdn-idea-global.zingfront.com/report-preview/2025/Insight-into-Marketing-Insights-%26-Ad-Creatives-Analysis-of-Global-Mobile-Games-in-2025.pdf)

단순 조작·짧은 성공·명확한 CTA는 기존 UX 자료와도 일치하지만, 이번 기획의 중심은 **사용자가 제시한 판매와 재투자의 보상 사이클**이다. [Playable Factory UX 가이드](https://playablefactory.com/blog/ux-matters-designing-playable-ads-for-maximum-engagement)

## 10. 문서·개발 상태

최신 세트: `tycoon-playable-v2.md`, `tycoon-claude-brief-v2.md`, `tycoon-balance-v2.json`. v1은 이전 제안 기록이며 구현 기준으로 사용하지 않는다.

`CLAUDE.md`와 `docs/cocos-notes`의 코드 재사용·씬 격리·사용자 인스펙터 값 보존 규칙을 따른다. 이전에 문서에 남아 있던 FBX 장애와 카드 투명 설정 충돌의 현재 해결 여부는 이번 기획 개정에서 확인하지 않았다. Claude는 개발 착수 시 현재 상태를 확인하고, 문서의 오래된 경로·zip 업로드 설명보다 현재 프로젝트와 최신 공식 규격을 기준으로 한다.

이번 작업은 기획·구현 브리프·수치 개정이다. 엔진 코드·씬·에셋을 변경하거나 Claude에 메시지를 전송하지 않았다. 산술 검산과 실제 플레이/용량/성능 검증은 구분한다.

### 작성 시 검산 결과

저장된 v2 JSON을 다시 읽어 기준 이벤트 장부를 계산했다. 목재 발행·판매60개(플레이어42/일꾼18), 매출300코인, 투자180코인, 지갑120코인·지급함0으로 일치했다. 각 이벤트에서 목재·코인 보존, 등짐·지급함 한도, 투자 순서를 확인했다. U3 이후 플레이어 목재12개와 두 일꾼 매출을 회수한 조건도 충족했다.

추가 산술 시나리오에서 U3 전에 채집한 플레이어 목재로 대체하면 정상 종료 자격을 얻지 못하고, 첫 판매 대금을 회수하지 않으면 첫 투자 비용이 부족함을 확인했다. 일꾼 주기 예산8초와 HTML 계획 예산4,500,000바이트도 합계가 맞는다. **이는 기획 데이터의 계산 검증이며, 엔진 거래 처리·소켓 손맛·실제 완료 시간·빌드 크기·성능 검증은 아니다.**
