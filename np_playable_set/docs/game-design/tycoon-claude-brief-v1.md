# Claude Code 전달용 — 타이쿤 플레이어블 v1

> **대체된 이전 브리프. 개발에 사용하지 않는다.** 최신 기준은 `tycoon-claude-brief-v2.md`와 `tycoon-playable-v2.md`, `tycoon-balance-v2.json`이다. 목재 직접 건설 방식은 판매→코인 회수→투자 방식으로 변경됐다.

작성일: 2026-09-16

**상태: 사용자가 검토할 구현 브리프. 이 파일 작성은 개발 착수 지시를 외부로 전송한 것이 아니다.** 아래 작업은 사용자가 이 안으로 개발을 진행하도록 지시했을 때 적용한다.

## 목표

플레이어가 나무를 캐고, 목재를 건설에 투입하고, 일꾼을 고용하고, 기지를 확장하여 자동화 생산이 증가하는 체험을 만든다. 정상 경로 목표는 첫 조작 후 45~60초다.

기획의 중심은 **내가 하던 일을 일꾼이 대신하기 시작하는 변화**다. 첫 일꾼의 실제 생산·운반·입고를 보여주고, 최종 업그레이드 뒤 두 일꾼이 각각 납품한 것을 확인한 다음 성공 CTA를 노출한다.

## 읽을 문서와 판단 우선순위

1. 사용자의 최신 확정 사항.
2. 프로젝트 루트 `CLAUDE.md`의 기존 코드·에셋 보호 규칙.
3. 같은 폴더 `tycoon-playable-v1.md`의 상세 흐름·예외·검수 조건.
4. `tycoon-balance-v1.json`의 숫자 원본. 자동 런타임 설정으로 취급하지 않는다.
5. `docs/cocos-notes/`의 엔진 경험 기록과 최신 공식 Cocos/AppLovin 문서.

기획값은 기존 라이브 씬 값이 아니다. 코드 기본값에 일괄 대입하지 말고, 사용자에게 채택된 수치만 씬3 인스펙터 설정으로 반영한다. 문서가 충돌하면 사용자 결정·최신 공식 규격·실제 저장 상태를 구분하여 해결한다.

## 첫 작업: 재사용 가능성·기준 빌드 확인

개발 전에 다음 표를 채워 보고한다. 전체 프로젝트를 다시 설계할 필요는 없다.

| 항목 | 확인 질문 |
|---|---|
| 캐릭터 상태 | `CLAUDE.md`의 2026-09-16 FBX 임포터 장애가 현재도 남아 있는가? missing·셰이더 오류 없이 표시되는가? |
| 채집 | `Player`·`Choppable`이 자동 타격과 개별 목재 보상을 지원하는가? |
| 경제 | `CoinPool`·`CoinStack`의 수량/시각 모델이 분리되어 있는가? 예약·상한을 추가할 지점은 어디인가? |
| 지불 | `Socket`·`SocketManager`가 비용·순서·보상 이벤트만으로 재사용 가능한가? 러쉬가 기본 연동되어 있지는 않은가? |
| 일꾼 | `CoinCourierManager`는 운반만 하는가, 생산도 하는가? 현재 노선 데이터가 설정되어 있는가? |
| 건물·길 | `BuildingTrigger`·`VirtualWall` 등을 활용하여 활성화와 통행을 함께 바꿀 수 있는가? |
| 가이드·CTA | 기존 안내·월드 UI·CtaClick을 어느 범위까지 재사용할 수 있는가? |
| 기준 빌드 | 씬3만 포함한 release 단일 HTML의 실제 바이트 수와 주요 내장 데이터는 무엇인가? |

기획자는 이번 문서 작성 중 씬·에셋·스크립트를 직접 검사하지 않았다. 문서에 이름이 있는 기능을 ‘이미 동작 확인된 기능’이라고 보고하지 않는다. 캐릭터가 깨진 상태라면 그 상태의 빌드를 출고 기준으로 쓰지 않는다.

## 필수 구현 범위

### A. 채집과 경제

- 재화 ID 하나(`wood`에 해당하는 개념). 기존 Coin 클래스명을 일괄 변경하지 않는다.
- 시작 목재 0, 플레이어 보관 12, 창고 120.
- 나무 HP 3, 채집력 1, 보상 6. 최초 타격 예열 0.15초, 타격 간격 0.45초 후보.
- 새 벌목 시작 시 등짐 자리와 드롭 풀 6개를 예약한다. 공간이 없으면 납품을 안내한다.
- 플레이어용 나무 6그루, 소진 후 8초 재생성. 일꾼 작업 지점 2개는 별도 예약.
- 등짐과 창고를 다른 보관 위치로 관리한다. 지불은 등짐 우선, 창고 다음이다.
- 플레이어가 활성 납품 구역 안에 있을 때만 지불. 0.10초당 1개, 부분 지불 유지.
- 지불/획득 시 소유권 이전은 한 번만. 초과 지불·잔고 음수·반복 보상 방지.

### B. 데이터 기반 단계

| 단계 | 비용 | 보상 |
|---|---:|---|
| S1 | 목재 6 | 창고 사용 |
| S2 | 목재 12 | 일꾼 1명 |
| S3 | 목재 18 | 길·가공소 부지·두 번째 작업 지점 공개 |
| S4 | 목재 24 | 일꾼 2명, 각 일꾼 생산량 12 |

상태는 예를 들어 `잠김 → 납품 가능 → 완성 연출 → 완료`로 구분한다. 구체적인 코드 구조와 파일명은 기존 모듈을 보고 정한다. 비용 도달을 원자적으로 한 번만 처리하고, UI·건물·일꾼·가이드는 그 이벤트를 받아 반응한다. 진행 매니저에 벌목·이동·재화·광고 코드를 전부 넣지 않는다.

오직 현재 단계만 지불받는다. 다음 단계는 완성 이벤트 뒤 열린다. 시간이 지나면 자동으로 단계를 넘기는 방식은 쓰지 않는다. 미설정 모듈은 무동작이어야 한다.

### C. 일꾼 생산

- 고정 경유점으로 작업 구역↔창고 왕복. 새 경로 탐색/물리 라이브러리 없음.
- 업그레이드 전 6초당 6개, 업그레이드 후 각각 6초당 12개 목표. 자세한 이동·작업·납품 시간 예산은 숫자 파일 참조.
- 일꾼은 작업이 끝나면 목재를 운반하고 창고에 도착해 납품한다. 생산 타이머로 창고에 미리 돈을 넣지 않는다.
- 업그레이드는 다음 작업 완료분부터. 이미 든 짐의 수량은 바꾸지 않는다.
- 창고 포화 시 남은 짐을 가지고 대기한다. 빈 공간이 생기면 납품 재개.
- 일꾼은 현재 건설 구역에 직접 지불하지 않는다. 플레이어의 방문이 건설 진행을 결정한다.

### D. 화면·종료·광고 연결

- 첫 화면에 플레이어·나무·0/6 건설 구역이 함께 보인다.
- 손가락 이동 가이드와 활성 목표 하나. 무진행 4초 시 안내만 재표시.
- S4 완료 후 최소 6초 + 두 일꾼의 S4 이후 실제 납품 각 1회를 만족하면 성공 패널.
- 첫 입력 이후 활성 시간 70초에도 미완료면 현재 기지에 보조 CTA만 노출. 거짓 성공·강제 스토어 이동 없음.
- 성공 패널 뒤에도 배경 생산/이동 가능. 다음 확장 미리보기는 잠긴 장식으로 구분.
- 첫 입력 전 전체 음소거·진행 정지. 숨김 시 게임/오디오 일시정지. 복귀 시 큰 dt로 생산이 폭주하지 않게 처리.
- 기존 어댑터/CtaClick을 사용하되 MRAID 준비·첫 탭·명시적 설치 터치·양방향 화면·WebGL 폴백을 최신 공식 규격으로 검사.
- 임의 외부 분석 요청·추가 SDK·런타임 원격 에셋 다운로드 없음.

## 최적화 구현 작업

1. 기준 빌드→경제 완주→최종 아트의 각 단계에서 HTML 크기를 기록한다. 내부 목표 4,500,000 B 이하, 출고 5,000,000 B 미만.
2. 단일 씬 출고 포함 목록과 내장 데이터 디코딩으로 미사용 의존성을 판별한다. 로더 문자열만 보고 라이브러리가 포함됐다고 결론 내리지 않는다.
3. 통나무 최대 76개 표시, 캐릭터 3명, 나무 8그루, 파티클 24개 상한. 수량이 많아져도 실제 재화를 버리지 않는다.
4. 드롭·운반·전달 효과 풀, 비행 연출 수 제한, 숫자 변경 시만 UI 갱신을 구현한다.
5. 첫 고용/최종 완성 직전 대량 할당·셰이더 컴파일·텍스처 업로드를 피하도록 준비한다. 준비 시간도 함께 측정한다.
6. 같은 통나무/불투명 나무의 메시·머티리얼 공유와 인스턴싱을 측정한다. 카드 개별 MaterialInstance와 실시간 스켈레탈 캐릭터를 자동 배칭되는 것으로 계산하지 않는다.
7. 동적 그림자 0패스 목표, 기존 가짜 그림자 재사용. standard 몸체의 재질을 임의로 교체하지 않는다.
8. 투명 카드 여백·겹침을 줄인다. 반투명 그림자가 있는 이미지를 무조건 컷아웃으로 전환하지 않는다.
9. 실제 GPU 병목에 따라 렌더 긴 변 1280→960, 부수 효과·장식 순서로 낮추는 설정을 마련한다.
10. 평균 fps뿐 아니라 구간별 p95/p99 프레임 시간·100ms 초과 정지를 기록한다. 기준 기기와 화면 방향을 보고에 적는다.

## 자산·기존 씬 보호

- 씬3 변경 에셋은 기존 격리 규칙에 맞추며, 공유 2D 카드 예외를 유지한다.
- 공유 스크립트를 씬별로 복제하지 않는다. 새 프로퍼티 기본값은 기존 씬 동작을 유지한다.
- `@property` 이름·스크립트 meta/CID·에셋 uuid를 보존한다.
- 사용자가 조정한 목재 자식 스케일·회전, 캐릭터 본, 카드 스케일/접점/법선 오프셋을 초기화하지 않는다.
- 편집기 상태와 저장된 씬/프리팹을 구분하고, 변경 후 실제 저장 결과와 실행 화면으로 검증한다.
- 공유 코드·프로젝트 Feature Cropping을 수정하면 씬1·2 영향도 확인한다.
